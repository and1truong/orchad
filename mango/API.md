# Model Gateway 0.1 API subset

Base development URL: http://127.0.0.1:4311. Production HTTPS. This is a documented OpenAI Chat Completions-compatible **subset**, not a drop-in implementation of the entire OpenAI API.

| Route | Authentication | Response |
| --- | --- | --- |
| GET /health | none | status: ok only |
| GET /v1/models | bearer | object list, allowlisted model data |
| POST /v1/chat/completions | bearer | one chat.completion or SSE chat.completion.chunk frames |

api.schema.json supplies Draft 7 schemas for ChatRequest, Message, ToolCall, Completion, CompletionChunk, Models and Error. Generate it from the actual runtime request schema with npm run schema. Semantic message ordering and state authentication are additional validation described here.

Request fields: model, messages, optional tools, tool_choice (auto/none), n (only 1), stream (boolean), max_completion_tokens. Defaults: stream false, tool_choice auto, n 1, output limit min(2048, model limit). Unknown top-level fields and unsupported values return HTTP 400. There is no temperature, arbitrary headers, base URL, tenantId, userId, reasoning, multimodal, parallel-tools option or provider credential field.

Messages require role and content. Roles: system, user, assistant, tool. Content is text, or null for assistant function calls. Assistant tool_calls contain id, type function, function.name and function.arguments as a completed JSON string. Tool results require tool_call_id and text content. All pending tool calls must receive one result before the next non-tool message; unknown/duplicate result IDs or duplicate call IDs fail. Tools have type function and function name, optional description, and parameters object JSON Schema. No remote schema loading. maxItems/size limits are in the schema and SECURITY.md.

Extension x_gateway_state is an opaque string permitted only on assistant messages. State authenticates the exact assistant content/calls, principal, provider and model and expires after 24 hours. Changing it, changing bound content, replaying to another principal/model/provider, or using an expired token returns 400. Same-principal replay with the same provider/model/message is supported. It is metadata, not an instruction, credential or reasoning display.

Streaming sends SSE data frames containing content or tool argument deltas, a final choice with finish_reason and optional x_gateway_state, an optional usage frame with choices empty, then data: [DONE]. State appears on the final choice delta only. Providers are fully normalized; metadata is collected before this final delta. A gateway failure after headers sends a sanitized error frame and closes without [DONE]. Consumers must require a final choice and [DONE] before executing tools. A length or content_filter finish reason is an incomplete/rejected turn, never permission to dispatch tools.

Success finish_reason values: stop, tool_calls, length, content_filter. Nonstreaming returns the same assembled assistant and nullable usage. Unknown/provisional usage is null in the API and retains null token columns plus explicit usage_status in the ledger; it is never fabricated as zero. Ledger status records inference success/failure, timeout and cancellation separately.

x_gateway_capabilities on each model lists text, streaming, functionTools, max_completion_tokens and compatibility restrictions. No provider key is returned. x-request-id is generated by the gateway and matches the usage correlation ID; client-supplied correlation headers are not trusted as authority.

Errors have error.message, error.type gateway_error, error.code. Typical HTTP status: 400 invalid schema/history/state or unsupported feature; 401 missing/revoked bearer; 403 denied model/origin; 413 body limit; 429 rate, concurrency, quota or upstream rate failure; 502 sanitized upstream failure; 504 upstream timeout. A disconnected request can be recorded as cancelled/499 but cannot reliably receive a response. Provider exception bodies/headers are never passed through.

No app tools are executed on this server. A nonstreaming/streaming tool response only describes a function invocation for the trusted host.
