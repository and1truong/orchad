# ADR-093: Noncommunicating asset activities

Launchable asset leaves use the immutable package resource host and the same capability, session, tenant, learner and binding checks as SCOs. Auxiliary dependency assets remain distinct from launchable activities. Asset-only packages can play, but cannot create an empty official completion proof.

The isolated asset player exposes neither SCORM API and omits CMI, sequencing snapshots and mapped working stores from its bootstrap. Its LMS Continue/End controls send only sequence, revision and navigation to a separate advance endpoint. SCO capabilities cannot use that endpoint; asset capabilities cannot submit a CMI checkpoint. Unknown fields, score, shared-data writes and client sequencing state are refused. Host-derived state, navigation, rollup, revision, receipt, audit and any completion projection use the existing single transaction. Exact original action bytes determine receipt identity; retries after a lost response do not navigate twice. Receipt replay still requires live authorization.

For 2004, the real trusted engine applies the authored delivery controls, auto-completion/objective defaults and sequencing/rollup. Controls marked completionSetByContent/objectiveSetByContent are preserved, even if the noncommunicating asset cannot provide those values. The UI follows effective ADL hideLMSUI and valid engine navigation. Choice-only organizations can deliver an authored choice through the engine when flow start is unavailable. Hidden presentation does not itself forbid an otherwise valid navigation request.

For 1.2, a human LMS advance records browsed and zero reported session time; it can satisfy an explicit AICC browsed comparison, never an implicit passed/completed requirement. Continue selects the next authorized activity. Viewing is not proof of reading. Assets never provide graded CMI evidence: official projection still requires every required selected SCO's accepted policy and the 2004 root rollup. Asset-only packages remain unofficial under the existing SCO completion contract.

Evidence: four-edition mixed asset/SCO and asset-only domain cases; forged action fields, endpoint separation, audit rollback, session revocation, hidden controls, choice-only flow and authored tracking controls. Four built Chromium journeys verify absent APIs, package CSS, lost-ACK exact retry, authenticated next-SCO delivery and one SCO-only proof. This does not establish commercial authoring compatibility, reference-engine parity, standards certification or production isolation.
