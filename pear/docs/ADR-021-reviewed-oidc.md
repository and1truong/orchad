# ADR-021: Reviewed OIDC subjects and fail-closed production identity

Pear implements an explicit Authorization Code + PKCE S256 profile using [OIDC Core 1.0 errata 2](https://openid.net/specs/openid-connect-core-1_0-errata2.html), [RFC 7636](https://www.rfc-editor.org/rfc/rfc7636.html) and [OAuth security BCP RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html). Configuration pins one issuer/client and issuer-origin authorization/token/JWKS endpoints. HTTPS and secure session cookies are required. No dynamic issuer discovery, implicit flow, generic OAuth access-token login or automatic account linking is supported.

Server-created 256-bit state, nonce, browser-binding cookie and PKCE verifier are stored in bounded five-minute transactions. A provider fingerprint invalidates pending flows after configuration changes. Same-origin start requests are rate/capacity bounded. Callback validates state/binding/expiry and atomically consumes once before code exchange. Token/JWKS fetches reject redirects, timeout after five seconds and bound bodies to 64 KiB. No access/refresh token is retained.

Profile: RS256 only, RSA ≥2048, distinct bounded JWKS kids with rotation refresh, verified signature and exact issuer/client/nonce. One audience only; multiple audiences are rejected explicitly. Issued-at, expiry and optional not-before are checked. Untrusted token key URLs/embedded keys/critical headers fail. Token claims never grant roles, tenant, manager relationships or display identity.

Migration 016 maps a reviewed issuer+subject to an existing active same-tenant account. Only live tenant administrators may link/unlink through human HTTP routes with CSRF/session epoch/library CAS/exact retry/audit. Mapping mutations revoke target sessions atomically and cannot silently reassign a subject. Content admins/managers/assessors/learners cannot manage identity settings; no mapping tool exists in the agent catalog. Login checks live mapping/account in its session transaction, rotates prior session, records an audit entry and retains normal eight-hour local session policy.

The normal startup accepts PEAR_OIDC_CONFIG JSON with issuer, authorizationEndpoint, tokenEndpoint, jwksUri, clientId and optional clientSecret, plus secure HTTPS APP_ORIGIN/COOKIE_SECURE. No credentials or real IdP have been configured here. identityFixture permits only loopback HTTP through programmatic CI setup and is never read from startup environment configuration. The synthetic password route remains development-only; production identity is disabled when no provider is configured.

Seven Node/domain/HTTP fixtures cover disabled/config gates, real loopback signed code exchange, binding/expiry/replay/config changes, signature/claim negatives, public-key rotation, live mapping/roles/CAS/rollback and human route integrity. A real browser fixture follows actual cross-host localhost/127.0.0.1 redirects, reviews a mapping as admin and rejects forged admin claims for the learner. These are internal fixtures, not evidence for any commercial IdP account.

Remaining G17: authorized real-provider sandbox, provider-specific discovery/client-auth profiles, SCIM provisioning/group support, logout/back-channel/front-channel/session policy review and deployment operations. No production SSO/provider-wide conformance claim.
