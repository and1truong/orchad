# ADR-033: Durable Pear recovery with live host authority
A shared durable runner can recover an approved Pear mutation whose domain transaction committed but whose host response was lost. The journal re-enters with the original request, arguments, expected revision and idempotency key. The rebound actual Lime HostPolicy checks consent/target/session, obtains a fresh mutation approval, and the actual Pear HTTP backend performs live ACL before keyed result lookup.
Historical successful results retain their original revisions. The runner now preserves the maximum known live revision per target when such a result arrives; otherwise a recovered old response can regress CAS below the current bind-time revision and make the next legitimate write fail stale.
The dedicated shared-runner lane installs Pear/Lime dependencies and exercises actual Pi durable scheduling, scripted real Mango gateway, actual HostPolicy and actual Pear HTTP/SQLite. Fault injection removes the checkpoint owner lease after a committed response is deliberately withheld. This is simulated process death with a parked test zombie, not a production kill/restart deployment claim.
Regressions cover identical replay envelope and single bookmark effect, an intervening human mutation, a subsequent valid CAS write, persistent transcript, zero official completion/grade/certificate effects and absence of bearer/cookie/CSRF/password values in checkpoint bytes. Consent revocation, logout and deactivation each block re-entry before another HTTP dispatch.
This verifies the recovery substrate for a Pear bookmark. It does not add durable workflow selection/system guidance to the Lime UI, evaluate model usefulness, install Slack/Teams or imply background notification delivery.
