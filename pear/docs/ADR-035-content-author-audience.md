# ADR-035: Immutable course/item audience and author authority
Self-authored course and standalone item versions accept an explicit tenant or author audience, defaulting existing fixtures to tenant. An additive ownership ledger attributes new content to its creator and existing content to a deterministic tenant administrator where available. An audience restricted to author requires that owner for learner discovery/direct reading; administrator draft/file review remains an explicit authoring privilege. Content Admins cannot edit another author's restricted draft, narrow another author's public source or replay an old successful write after author authority is lost.

Discovery, direct reads, enrollment, assignment recipients and scheduled reconciliation, pinned course/item references, curation/replacements, translation identity/setting disclosure, rating versions, raw media and xAPI actor validation enforce the audience. A restricted item cannot be copied into a wider course or collection. Uploaded bytes do not become a shared authoring asset until explicitly attached to an authorized shared draft/version. Private publication/enrollment/completion/assignment facts are excluded from organization integration events.

Publication changes the audience of a new immutable version. Existing legitimate public pins and historical public snapshots remain readable; withdrawal/retirement retains learning history. This is self-authored audience control, not commercial license revocation. Licensed provider entitlement/revocation requires the separate provider-policy layer and remains open. Scopes are tenant/author, matching current collection scopes; group/portal-specific sharing and provider policies remain open.

Regressions exercise cross-role direct guesses, author edits and key replay, references, files, immutable public pins, actual HTTP human/bridge/raw-file paths and a browser authoring/publication journey. Exact-head CI is pending; no role parity/compliance/epic closure is claimed.
