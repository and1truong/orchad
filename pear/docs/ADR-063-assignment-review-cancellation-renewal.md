# ADR-063: Preserve cancelled/expired review history while offering a fresh review
Status: implemented, exact-head CI pending.
The original ADR-062 expired-offer renewal gap is addressed without changing official learning. Current coordinator may cancel an own pending review (tenant admin oversight permitted); learner accepts neither cancelled nor expired records. Cancellation requires a separate human confirmation.
A fresh offer for the same source/version must name the last review ID observed, after that review is cancelled or expired. Live pending reviews cannot be superseded. The source/version history remains bounded to the existing 5000 tenant quota. Migration 038 rebuilds only the review table, preserving existing IDs/state/receipts and adding predecessor/cancellation actor fields.
Optional previousReviewId keeps original first-offer calls compatible. Original-key immediate retry checks current roles/relationship/content/source, expiry and exact predecessor; old keys never resurrect expired/cancelled offers or cancel another actor's decision. New keys cannot replay a completed cancellation or create duplicate live reviews. All checks occur before receipts and within IMMEDIATE transactions; audit and both revisions roll back together.
Four domain tests include actual 037-to-038 migration, unknown-key negative cases, cancellation receipt/authority rollback, and renewal without changing assignment state. One browser test exercises explicit expired-review renewal and cancellation. Cycle/essay/submission/nonquiz migration and exact reference semantics remain OPEN. No background messaging or actual integrations are activated.
