# ADR-016: Explicit promotions and reviewed retirement alternatives

Internal Pear policy; provider lifecycle feeds and exact Go1 portal semantics remain unverified.

Organization content admins/admins set endorsed, featured, spotlight and retiring metadata. Published tenant-authorized metadata is paginated and ordered spotlight, featured, endorsed, kind, ID. Reasons name the explicit organization decision; no algorithmic recommendation or learning outcome is implied. Marking retiring is advisory; retirement stops new direct discovery/enrollment under existing policy.

Retirement with a replacement requires a reviewed hash of exact source/replacement versions, aggregate pinned enrollment counts, immutable course/collection dependencies (including nested awards) and assignment-plan state. The live transaction recomputes this snapshot. Impact or selected replacement changes require another review. Replacement must be distinct, same kind and currently published in the tenant. Different language is disclosed.

No enrollment, progress, answer, credit, certificate, published reference or assignment plan is rewritten. Existing pinned course/award reference semantics remain in force. Direct future assignment jobs for retired targets become unavailable until a separately reviewed plan edit. Learners can look up an explicit alternative and choose to preview/track/enroll it; unavailable or absent alternatives return a reason, never an unlicensed fallback. Retiring an alternative invalidates its availability. A committed retirement key can reconcile after retirement under live role/tenant checks.

Impact returns aggregate counts without learner identities or private statements/files. Promotion and alternative metadata excludes raw bodies, quiz keys and asset IDs. Content admins do not gain integration, identity or learner assessment authority. Writes use existing library CAS, atomic audit/idempotency and live role scope. Historical contents and ledgers are preserved.
