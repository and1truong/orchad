# ADR-095: Unicode characterstring boundaries

ADL 2004 RTE 4.1.1.7 defines characterstring SPM in characters rather than UTF-8/UTF-16 encoding units. Pear now counts Unicode scalar values for its CMI/shared-store string quotas. Supplementary characters occupy one character; combining sequences retain their individual characters. Do not normalize, truncate or replace content data. Lone high/low surrogates are invalid scalar strings and fail before content can queue a checkpoint or the server can accept one. Exact UTF-8 byte quotas for HTTP envelopes, runtime capacity and system storage remain independent.

The pinned 3.4.5 plain characterstring regexes counted UTF-16 units. A narrow checksum-locked correction in both actual ESM entries gives only the simple CMIString bounded whole-string patterns Unicode matching; the 2004 BMP-only character class becomes the full scalar-compatible class. Vocabulary, identifier, language-string and interaction grammars keep their original matching rules. Do not switch every engine regex to Unicode mode: some existing grammars contain legacy escapes. The facade/server reject lone surrogates independently of the reused regex implementation.

The admitted suspend-data bounds remain 4096 for 1.2, 4000 for 2004 second edition and 64000 for third/fourth editions. SPM is a minimum implementation capacity, not a universal maximum prescribed to every LMS; these are this integration's published bounded capacities. A larger upstream 1.2 extension does not silently exceed the host's capacity: the synchronous facade refuses it with 405. Plain 2004 location/comment-location and fourth-edition mapped working stores count supplementary characters correctly. Readonly launch values, original map permissions, exact receipt hashing, transaction rollback and official proof rules remain unchanged.

Behavior adaptation is `pear-unicode-v4`. Exact ESM SHA-256: 2004 `8c6468541bf6f07353307758f5a828e7e9e04da0619c859500c9b108015db5da`; 1.2 `2f8591ab1f08bd696ff11dc72b1e92c197d12512978ef870a39507ed9567e366`. Version/cardinality/checksum verification retains known pristine/logging/selection/limits paths and idempotence, refuses unexpected bytes/version and preserves MIT notices. A real installer test reconstructs exact known pristine/logging/selection/limits 2004 and pristine 1.2 bytes, invokes the actual install script and compares both complete outputs; malformed bytes and a future version fail closed. Existing selection-v2/limits-v3 snapshots remain readable; the engine version and launch/package scope checks still apply.

Four-edition domain cases cover exact supplementary suspend-data bounds, over-limit and lone-surrogate failures, nonmutation after refusal, durable ACK/exact replay, close/resume and forged checkpoint rollback without proof. Local/system mapped stores support 64000 supplementary characters with atomic refusals. Three built Chromium edition journeys use package-owned external JavaScript through the real isolated runtime, save/resume the boundary string, lose/retry a finish ACK and complete through authenticated navigation. A fixture passing these cases does not establish exhaustive localized-string, identifier, interaction, error-precedence, reference-engine or production conformance. Those gaps remain in epic #133.

Primary reference: [ADL SCORM 2004 fourth-edition RTE](https://lms.technology/for/scorm/2004/4th_edition/standards/SCORM_2004_4ED_v1_1_RTE_20090814.pdf), section 4.1.1.7 and the relevant data-element SPM tables; the archived document is authored by ADL, not a substitute specification written by its hosting site.

Integrated local acceptance: 553 domain tests across 82 isolated files and 64 built Chromium cases PASS, plus build/typecheck. The duration file uses isolated named cases when its combined process lacks a complete TAP footer; incomplete zero-exit output is not counted. The expanded actual installer upgrade test was rerun PASS after the full run. Exact remote head/tree and remote CI status belong in the PR/epic record.

Access-precedence follow-up: scalar prevalidation uses the same recognized-writable field definitions as host replay. Readonly/undefined elements retain their standard errors; mapped readonly stores and unsupported-edition ADL data are checked before value rejection. Nine Unicode and eight existing 2004 API/server cases pass in isolated processes with complete TAP footers, three rebuilt Unicode browser journeys and build/typecheck PASS. The earlier full 553/64 result belongs to the pre-follow-up tree; do not relabel it as this exact head.
