# ADR-044: entitled metadata discovery and explicit human launch
Epic #49 G02/G03/G10. Extends ADR-043 without claiming commercial provider conformance.

Three bounded learner read tools expose own currently entitled metadata and launch history. Bridge reads require the trusted connection's model metadata permission. Missing or revoked rights hide metadata in search/history; own opaque source/version/time history remains separate from official learning. Human UI can review metadata under human rights even when model processing is denied.

A human-only confirmed write captures the exact current source version, own account auth-version, timestamp and a 60-second opaque launch ID. Existing core live ACL, original semantic key, CAS, atomic launch/idempotency/audit/revision apply. No automatic external navigation occurs. A separate human link opens a new tab with noopener/noreferrer. The GET requires an own current cookie and auth-version, unexpired launch, current active client/admin/license/item/grant and unchanged source version. Only the exact trusted HTTPS launch origin plus a fixed encoded source path can redirect. No bearer, ticket, account address or secret goes to the provider URL or agent catalog. The provider handles its own session and content rights after navigation.

The short-lived GET is deliberately an own-cookie launch endpoint exempt from the API epoch header, matching a native anchor link; it is auth-version bound, not a per-tab session token. Logout removes the cookie; a newly authenticated same-account cookie could open an otherwise still current 60-second launch. This is not a promise to revoke a remote provider session after redirect. No completion/grade/timer/certificate/enrollment is written. 2,500 launch records per learner bounds retained history; deletion/retention policy remains open.

Three domain/actual HTTP and one EN/VI mobile browser regression are authored. The browser test verifies the actual own-cookie redirect response without contacting the synthetic external origin. The actual provider launch path/protocol must be reviewed against a partner contract before use. Admin binding UI and startup/deployment configuration remain next layers. Actual Go1 account/license and partner revocation/wire conformance remain BLOCKED/NOT VERIFIED.
