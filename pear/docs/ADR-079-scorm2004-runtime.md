# ADR-079: Edition-aware SCORM 2004 durable runtime

Epic #133 S5 extends S4 on its independent stack. Reuse the pinned MIT scorm-again 3.4.5 data model in both the content wrapper and the server. Content receives only the eight synchronous `API_1484_11` methods. SCORM 1.2 continues to receive only `API`.

The initial 2004 playback profile is one SCO without sequencing extensions. The importer retains all original bytes and edition markers. Complex activity trees, shared data and sequencing are explicitly refused until a trusted sequencing adapter is installed; no downgrade to 1.2 or flattened traversal occurs.

Each checkpoint replays changed writable fields through a fresh real engine seeded with server-owned learner identity, credit/mode, entry, total time and immutable manifest data. It validates edition-specific suspend data limits (4000 for 2nd edition; 64000 for 3rd/4th), bounded collection shapes and timeintervals. CMI, duration deltas, revision, immutable receipt, completion projection and audit share one SQLite transaction. Retry preserves sequence/payload; reopening restores acknowledged state and pending navigation. Runtime navigation is checkpointed separately from CMI because upstream CMI serialization omits ADL navigation. Cross-activity requests are unavailable in this slice.

2004 success and completion are independent. Every required SCO must terminate durably and report completed. The passed policy additionally requires success passed. The completed-or-passed authoring policy accepts completed even when success failed; minimum score still applies if configured. A scaled score is converted to a percentage; raw scores require a known min/max range. SCORM 1.2 raw scores already use the 0–100 scale and are no longer rescaled using optional bounds. Preview/practice cannot project enrollment completion; existing exact award/cycle, module, audience, retake and quiz/certificate rules still apply.

CAM `dataFromLMS`, `timeLimitAction` and `completionThreshold` use their case-sensitive 2004 spellings. Fourth-edition completion attributes follow their defaults; attributes are refused on older editions. Weighted completion awaits sequencing. Engine lexical quirks are handled narrowly: leading-dot numbers acquire a zero, and timezone timestamps without fractional seconds acquire `.00`; represented values are unchanged. Durations require ordered ISO components and centisecond precision. Calendar conversion follows the reused engine's 365-day year/30-day month policy; this policy is not a claim of calendar equivalence.

2004 snapshots have a 512 KiB UTF-8 quota and 16-entry queue; the HTTP envelope has a 544 KiB limit. The 1.2 CMI quota stays 128 KiB. The upstream engine counts string limits in UTF-16 code units, so supplementary Unicode characters consume two units; full Unicode SPM conformance remains an external acceptance finding. No SCORM certification, full engine parity, broad external-tool interoperability, production all-egress isolation or native execution claim is made.

Validation includes all three editions, API lifecycle/error behavior, comments/objectives/interactions, long non-ASCII suspend data, independent success/completion, threshold evaluation, forged read-only fields/containers, audit rollback, idempotency, cumulative time, SQLite reopen, preview separation and built browser resume/Terminate. Self-authored fixtures require no commercial license.

Primary references: [ADL SCORM 2004 4th Edition RTE v1.1](https://lms.technology/for/scorm/2004/4th_edition/standards/SCORM_2004_4ED_v1_1_RTE_20090814.pdf), [ADL CAM v1.1](https://lms.technology/for/scorm/2004/4th_edition/standards/SCORM_2004_4ED_v1_1_CAM_20090814.pdf), [Rustici runtime reference](https://scorm.com/scorm-explained/technical-scorm/run-time/run-time-reference/) and the pinned engine source/types. Specifications inform behavior; their text and proprietary packages are not redistributed.
