# ADR-011: Private award evidence PDFs

Award evidence is an immutable self-authored PDF uploaded by the learner against an active own award enrollment and an exact external criterion path in its pinned graph. Nested criteria use the root enrollment and fully qualified path. Uploading a file alone grants no credit. The learner must still confirm a statement and claimed amount; the pinned policy determines pending moderation or explicit self-attestation. Non-ongoing completed awards reject new file evidence; existing text-only supplemental evidence semantics remain compatible.

Assets use the existing bounded human upload endpoint, signatures, personal workspace CAS, live account/epoch checks, atomic audit and exact-key retry. Evidence PDFs inherit the 8 MiB per-object and 128 MiB/512-object tenant limits. Production upload remains closed until scanning/quarantine/storage is configured; format signatures are not a malware scan. No raw file transport is added to Bridge 0.1 and its 64 KiB/64-tool limits stay unchanged.

The file must belong to the same learner, tenant, enrollment and criterion. External records pin its immutable asset ID. Duplicate evidence is detected using file byte SHA-256 per enrollment/criterion, regardless of filename or statement; text-only records retain their old trimmed-statement hash. A future assignment cycle has its own enrollment and proof ledger. Migration 010 adds a nullable foreign key and preserves previous text evidence, identities, history and certificates.

The owner may retrieve their own file. Other readers must supply an actual matching record ID and be the tenant admin or a currently delegated assessor for that root award. Managers and content admins cannot retrieve learner evidence or publish it as content. Revoking a delegation or session removes access immediately; retained historical files do not grant continuing assessor authority. Human moderation results include the asset ID for authenticated download. Agent results expose only an attachment boolean and continue withholding statements, hashes and file IDs. No file bytes, launch ticket or storage URL enter a model request.

The human form offers an optional PDF, waits for upload completion before submitting, and preserves text-only evidence. Assessors download the exact stored PDF before recording their normal moderation decision. Official completion and certificates remain derived by the existing backend award evaluator.

Validation covers legacy migration, nested/ongoing pinning, wrong tenant/learner/criterion, content laundering denial, attachment withholding, duplicate-byte detection, revoked delegation/session, audit rollback and persistent retry/file bytes after database reopen. The real browser journey uploads a Chromium-generated PDF, downloads byte-identical evidence through the delegated assessor UI and verifies no certificate before moderation and a persisted certificate after acceptance. Full reference evidence formats and re-certification semantics remain unverified.
