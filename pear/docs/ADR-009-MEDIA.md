# ADR-009: immutable internal uploads and isolated interactive launch

Synthetic internal scope, 2026-10-06. Stack parent: assessment PR #67. No provider files, real personal data or deployed storage used.

Files live as immutable SQLite BLOBs with random IDs, tenant/owner, original display filename, SHA-256, size and upload operation key. No filesystem paths, arbitrary fetch, executable server files or archives are accepted. Content authors explicitly confirm ownership. Uploads are human-only with live account/role, Origin/Host/CSRF/session epoch, canonical library CAS and audit in the same immediate transaction. Exact valid retries precede CAS; payload conflicts and revoked authority fail. The binary route alone accepts 8 MiB; all Bridge routes retain 64 KiB. Each tenant is bounded to 128 MiB and 512 objects. HTML is further bounded to 64 KiB with valid UTF-8/no NUL. PDF/WAV/MP3/MP4 have format signature checks; these are not malware scanning or complete media validation.

Production uploads fail closed: a production malware scanner/quarantine/storage policy is not configured. Synthetic self-authored fixtures can be uploaded only with explicit development authentication enabled. Production scanning remains an open gate, not a PASS inferred from MIME or signature checks.

Uploaded content is pinned by immutable asset ID. Authoritative reusable-item materialization copies IDs and permissions into immutable course versions. A learner fetch must name the published item/version or own pinned enrollment/unlocked lesson. Other learners, tenants, retired standalone items and prerequisite bypasses fail. Existing enrolled snapshots retain their files when a source item retires. Raw file bodies and launch tickets are absent from agent tools; human-controlled downloads use session-bound fetch and revoked Blob URLs. PDF/HTML download responses are attachments with nosniff. Audio/video uses native controls and Blob URLs, with transcript required. Documents have human-authored text alternatives; interactive content requires a description/transcript. No package tracking or script-reported completion is trusted.

Interactive HTML uses a normal HTTP document response, not srcdoc or a Blob that would inherit Pear's script CSP. It executes with **an opaque origin** forced by both the iframe `sandbox="allow-scripts"` and response CSP `sandbox allow-scripts`; `allow-same-origin` is never granted. The route's CSP permits inline script/style only inside that opaque sandbox, denies connect/media/frames/form actions/base URLs, and permits only data images. Parent Pear's script CSP remains self-only. Permissions deny camera, microphone, geolocation, payment and USB. The server needs the authenticated cookie on the initial navigation to authorize launch but never sends that cookie, CSRF or epoch to the child. Child JavaScript cannot access cookies/storage, Pear DOM or Bridge. A short-lived signed ticket binds the current session hash, immutable ID, exact read context and 60-second expiry; every navigation rechecks live access. Restart invalidates tickets. No host postMessage listener grants authority. A script's fabricated completion/score is ignored.

References: [HTML iframe sandbox](https://html.spec.whatwg.org/multipage/iframe-embed-object.html), [Fastify buffer parser and body limits](https://fastify.dev/docs/latest/Reference/ContentTypeParser/). Browser evidence must demonstrate script execution plus blocked DOM/Bridge/cookies/storage/network. This is isolated HTML practice, not SCORM, xAPI, archive import or full interoperability parity.
