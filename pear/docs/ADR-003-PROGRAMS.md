# ADR 003 — Playlists, awards and external learning

Status: implemented for self-authored synthetic content; epic #49 remains open.

A playlist is an immutable published reading collection of course/item references. It has no enrollment, assignment, official completion or certificate. Tenant access shares it within the organization; author access restricts discovery to its author. Content administrators may edit shared drafts; private drafts remain author/admin scoped. Cross-portal sharing is not implemented.

An award is an assignable program with required/elective criteria, one or more alternatives per criterion, credits or hours and an independent target. Every required criterion must earn its configured credit amount and the total must meet the target. Multiple completed alternatives earn a criterion's credit once. Accepted external partial credits accumulate up to that criterion's cap. Pending/rejected records earn nothing. Ongoing awards never complete automatically or issue certificates.

Publication pins references to immutable content/nested award versions. Enrollment retains its first published root version, including subsequent duplicate assignment. Nested rules are evaluated within that root enrollment, without requiring a separate nested enrollment. Existing legitimate course completion satisfies a course criterion by content identity, including an older course version; this is an explicit reuse policy, not re-certification support. Retirement blocks new discovery/enrollment and preserves enrolled rules/evidence/certificates. New publication cannot reference unavailable/retired content. Drafts use conservative cycle checks; published traversal respects versions already pinned inside child snapshots. Boundaries: depth four, 32 expanded award nodes, 64 expanded criteria, 16 KiB expanded graph and a conservative 40 KiB progress-envelope budget, eight alternatives per criterion; cycles/oversize fail before publication.

External evidence requires the learner's authenticated human confirmation. No evidence-submit tool exists in the agent catalog. Evidence is scoped to the root enrollment and stable nested criterion path. Identical trimmed evidence cannot be submitted twice for that criterion; this is duplicate protection, not independent verification of evidence quality. Moderation is required by default. Explicit unmoderated configuration enables labelled self-attestation. A moderation decision requires a reason and is final; retry uses the original operation key. Evidence text stays in human APIs and is withheld from bridge reads and operational audit. Progress includes authoritative totals and up to three latest record summaries per alternative (20 summaries per root), with counts; the separately paginated assessor ledger retains all evidence history.

Admin may grant/revoke one active same-tenant assessor's scope on one award. An assessor gets no course authoring, roster, integration, assignment or organization-report powers. Manager assignment remains direct-report scoped. Account active/role/session checks are live, ahead of dedup. Assignment/moderation also increment affected learner revision. All ledger updates, program completion, certificate creation, idempotency and audit run in the same SQLite transaction.

Migration 003 is additive/idempotent. Program certificates identify the enrolled version and synthetic issuer and explicitly state they are not accredited. Text download is implemented; PDF, evidence uploads, re-certification, detailed localization, branding, notifications and cross-portal sharing remain separate capabilities. No model or agent loop is added to Pear.
