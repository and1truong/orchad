# ADR-043: reviewed provider metadata and entitlement ledger
Epic #49 G02/G03/G10. This layer is a restricted internal profile, `pear-provider-metadata/1`, not Go1 wire conformance or licensed content ingestion.

Trusted server construction supplies at most 32 exact provider/tenant/client bindings, future license expiry, and explicit model metadata rights. Default connections are empty. A configured HTTP app requires HTTPS/secure cookies; synthetic fixtures are loopback development only. No production connection or partner account is supplied here. Browser/model inputs cannot configure endpoints, licenses or rights.

A current same-tenant administrator-owned scoped integration bearer authenticates each write/read before replay and again inside the mutation transaction. Each feed event has an immutable UUID, sequential index and nondecreasing UTC timestamp. Object key ordering does not alter canonical semantic identity. Changed UUID/sequence payloads reject; gaps require reconciliation. Metadata is limited to title, summary, language, topic and intended duration. Bodies, answers, URLs and other fields reject. 16 KiB event, 4 KiB metadata, 1,000 items, 10,000 events and 10,000 grants bound each provider. Reconciliation returns whole bounded pages, no credential or licensed body.

Metadata, grant/revocation, event receipt, audit and tenant workspace revisions commit together. Audit failure rolls everything back. Retirement revokes current grants; a new item version does not restore old grants. Account/client/license/grant expiration and revocation are checked on current reads. Model reads also require explicit reviewed metadata permission. Metadata stays separate from course/item enrollment, grades, certificates, attempts and study timers. No external fetch, navigation, refresh worker or completion claim exists.

This PR implements backend feed and domain read primitives. Reviewed admin binding UI, learner discovery/launch/history and full provider lifecycle integration remain next layers. Actual licensed provider contract/account, commercial taxonomy/translations and partner wire/revocation conformance remain BLOCKED/NOT VERIFIED. Configured deployment/startup policy is still required; no environment variable enables this adapter automatically.
