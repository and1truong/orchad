# ADR-013: Pinned standalone reading ledgers

Published standalone content remains reusable, immutable content. A learner can separately track an exact visible published version in an own ledger. Tracking does not complete it; the learner explicitly confirms studying that version through a human-only operation. The completion policy is `learner_confirmed_reading`. No course enrollment, quiz attempt, award credit, official score or certificate is created. Items are distinguishable from assessed courses and rule-based awards in transcripts/reports.

Migration 012 creates a unique learner/item/version ledger with enrolled/completed timestamps and composite version foreign key. A new source version creates a separate optional learner entry. Editing, publishing or retiring source content never rewrites previous pinned content or reading history. New tracking requires a published tenant item; owners can read their already tracked history after retirement. Confirming an existing tracked retired version remains permitted. Completion time is monotonic: later confirmation retains its first timestamp.

Private enrollment reads and human completion require the current active owner/tenant, before retry and inside the master transaction. Tracking/confirmation use personal workspace CAS, exact-key retry and atomic revision/result/audit. Managers/admins/assessors cannot impersonate the learner or inspect another learner's private enrollment body. Manager reports may read metadata for current direct reports, with live scope on every preview/export. Tenant admins can report tenant metadata. No new permission to view private evidence or feedback is introduced.

Pinned reads preserve the original version's model-processing permission. Bridge results withhold text, links and transcripts when processing is prohibited, and omit file IDs even when permitted. Human file reads use the own item enrollment and exact pinned asset; source retirement is not a reason to deny that retained original, while wrong tenant/learner/enrollment/asset is denied. Interactive launch reuses the existing signed context, live access checks and opaque sandbox.

The human reader can track a displayed version and confirm reading only after an explicit checkbox. Own learning lists are paginated and reopen the pinned reader. Source-only preview remains available without tracking. Transcript/report rows have kind `item`, self-directed source, pinned version and confirmed-reading progress; no assessment score, cycle, deadline or certificate is implied. Existing saved report formats remain compatible; item filtering and selected-row CSV/print exports use the same authorized snapshot.

Validation covers old/new versions, retired source reads, private account/tenant scope, model/file withholding, original PDF access after retirement, guessed/mismatched contexts, revocation, repeated confirmation time, no course/award/assessment side effects, manager relationship changes, CSV scope, atomic rollback/CAS/retry, disk reopen and foreign keys. A real browser journey tracks version one, authors/retires version two, reopens version one, confirms reading, reloads and verifies the separate transcript row. Cross-portal sharing and provider content/standards semantics remain unverified.
