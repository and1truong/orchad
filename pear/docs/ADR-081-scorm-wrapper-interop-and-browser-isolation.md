# ADR-081: Licensed wrapper interoperability and observed browser isolation

Epic #133 S7 adds byte-pinned external wrappers to original course fixtures, rather than relabeling self-authored API calls as authoring-tool interoperability. The pipwerks wrapper exercises 1.2 and 2004 2nd/3rd/4th editions; the ADL developer-guide wrapper exercises 2004 3rd edition. Each built-player journey discovers the real API, stores an incomplete bookmark, closes, resumes, then finishes into authoritative enrollment evidence. See [fixture provenance and license notices](../tests/fixtures/scorm/NOTICE.md). The complete Roses course, commercial exports and legacy ADL Sample RTE are not bundled or represented as passing.

The adversarial built Chromium fixture attempts Pear cookie/storage access, agent/native bridge access, workers/service workers, fetch/XHR/WebSocket/beacon, external image/style/frame/form, popups and top/runtime navigation. It also forges status messages and a checkpoint envelope. A synthetic loopback sink observes zero requests; HTTP CSP/sandbox violations provide actual denial evidence. Worker construction alone does not prove execution: the test waits for the asynchronous error and verifies `worker-src`. The runtime's own navigation is tested because same-origin SCO code can alter the runtime DOM. Pear's `frame-src` confines that navigation in this Chromium lane. No browser flag disables web security. These observations do not prove universal egress isolation across engines, native WebViews or every possible browser channel.

Practice and preview now follow the authenticated server's next-SCO result with their existing consent and remain unofficial. Raw content messages only request authenticated reconciliation; they cannot select a SCO or claim saved progress. A built practice journey checks two finished SCOs and zero enrollments/proofs.

An explicit `test:scorm:lime` lane loads the actual unpacked extension and scripted local Mango boundary, reads permitted lesson metadata while SCORM is active, checks that CMI/capabilities stay out of tool results, and finishes through the human player. It runs after Lime build in CI and fails when extension startup or assertions fail. The workspace's Chromium headless-shell cannot start extension workers, so local browser passes exclude this lane and do not claim a Lime pass. Existing Coconut host acceptance is not native SCORM acceptance. Native SCORM playback/isolation, commercial/reference differential fixtures and production security remain open gates.

Validation: 17 built Chromium SCORM journeys; Pear build/typecheck and host typecheck. S6's eight acceptance jobs were green at `96cfcc4507524a18e19cb9b877dc7f6c8c212b80`. S7's actual extension CI outcome must be recorded separately after its PR runs.
