# ADR-068: Both humans confirm full-change direct assignment restart policy
Status: implemented, exact-head CI pending.
The current coordinator chooses objective_only (identical lesson retention) or fresh_course (no carried progress). Published source/latest content rights and active direct-report/admin assignment authority apply to both. A full-course offer requires resolved pending essay/submission work and cancelled bookings; any new pending work before acceptance blocks again. The learner must separately accept the exact stored mode. Omitted mode remains objective_only for older calls and receipts.
Migration 039 preserves historical review IDs/state/predecessors/receipts and defaults existing records to objective_only. The existing cancellation/expiry renewal chain cannot replace a live pending offer or silently change mode. Exact mode is checked before original-key lookup; mismatch and new-key duplicate are denied. A matching original key still requires current relationships/rights/target/expiry and a matching successor.
Full-course successor retains assigner/due date, copies zero lessons/answers/submissions/attendance/timer and withdraws the prior unfinished record without changing pinned history. Both revisions, receipt/redacted audit/source/successor/review state remain atomic. Assignment cycles are still rejected; no delivery pointer/plan version is silently changed.
Six domain tests cover actual direct assignment creation, due/assigner retention, resolved/pending essays, new pending submissions/bookings after proposal, exact-mode/authority replay and rollback/live-offer protection. The original 037 migration test now upgrades through 039 and checks legacy mode. One real two-role EN/VI browser journey confirms both humans and no fabricated completion. Exact reference/reset/recertification semantics and cycle version-change review remain OPEN.
