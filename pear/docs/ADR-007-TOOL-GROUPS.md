# ADR 007 — Bounded contextual catalogs

Status: implemented. Canonical Bridge 0.1 limits remain unchanged.

The report layer raised the administrator catalog to 62 tools. Pear now exposes complete named domain catalogs (learning, content, programs, people, assignments and reports), with small common discovery reads. The union covers every authorized tool; no list is truncated. Roles still determine available operations within each domain. Every group is checked against the 64-tool and 64-KiB descriptor bounds and the canonical host-safe schema dialect. Human-only assessment/evidence confirmation remains absent from every agent group.

The human chooses Assistant workspace, and normal navigation selects the corresponding domain. A non-default group qualifies documentId with `::group`. The backend strictly parses it and resolves the existing base workspace for tenant/owner/role checks and canonical revision updates. No extra workspace row or independent revision is created: reports, authoring and people changes share the same library CAS. All human UI operations remain independently authorized against the complete role catalog; bridge calls must belong to the selected descriptor group and mutations must still target the correct personal/library aggregate.

Describe and context use the same captured documentId. Changing domains changes the binding identity; existing host context/descriptor consent and pending approvals become stale. A production HostPolicy browser test proves that changing reports to people while awaiting approval dispatches no write and requires a new catalog. Browser export/session guards also include the qualified workspace. Direct HTTP clients must use the domain-qualified documentId when calling a tool outside the base workspace's default group. Default personal learning and library content IDs remain compatible.

This stack layer also adds a debug-only native acceptance barrier: wait for the actual trusted sidebar's initial binding-driven consent revocation before granting the smoke test's read consent. Without that barrier, a delayed sidebar heartbeat can erase a freshly granted test consent. Native timeout was reproduced twice on PR #64; the identical runner passed on PR #65, so this is timing stabilization, not a claim of a confirmed production permission bug. Native Rust compilation/runtime validation is delegated to the strict CI lane; the local workspace lacks Cargo/native libraries. No approval bypass, arbitrary delay or gate relaxation is introduced.
