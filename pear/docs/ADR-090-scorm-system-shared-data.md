# ADR-090 — persistent learner-scoped system shared data

Status: implemented successor to ADR-089; system-global objective maps remain separate required work.

Admit fourth-edition sharedDataGlobalToSystem=true, including its default. Schema 49 introduces learner-owned working data keyed by tenant, learner and manifest targetID, with revision, last source registration and timestamp. Composite account/registration foreign keys and immutable key identity constrain storage. This is content-reported mutable working data; existing official proofs and technical/domain history remain immutable. Migration does not promote local stores or reported status to system data or official learning.

For authorized normal enrollment bindings, load only targets declared anywhere in the original selected package. The current activity's API mapping and bootstrap read redaction still apply. Persist only the explicit current-SCO write delta, validated before navigation. No full backing snapshot from the client is accepted. Global stores use ordered last accepted explicit write semantics: transactions serialize updates; CMI-only checkpoints, unrelated keys and exact receipt retries do not overwrite newer values. This is an explicit concurrency policy, not a stale whole-snapshot replacement. Write revision/provenance increment once per accepted write.

Unofficial practice/preview system-mapped launches use private registration working data, keeping them separate from official system stores. They retain local replay/technical-retake behavior. This Pear authority policy is documented; it does not claim every commercial engine uses identical no-credit behavior. Local false scope retains ADR-089 semantics. Every registration/capability still receives live learner, tenant, session, package and enrollment authorization before read/write or receipt replay.

System working data joins the existing CMI/time/sequencing/proof/receipt transaction. Its UTF-8 value/key bytes and bounded metadata estimate count toward the 64 MiB tenant runtime capacity. Each learner has at most 4096 stores; per-SCO maps remain bounded to 64 and store/API/delta limits remain unchanged. Quota failure rolls back the entire checkpoint. Aggregate diagnostics add byte usage and disclose no values/target IDs. No agent mutation/runtime-data tools are introduced.

Whole-DB backup includes the working table and a coherent pre-backup revision; offline restore retains it while revoking old browser sessions and capabilities. Accepted data/history is retained on package security revocation, but that package's capabilities and even old receipt replay cannot read/write it. Existing authorized packages may still map the learner's retained working data. Production privacy/archival/retention/encryption/deployment decisions remain open; no purge or production execution is enabled.

References: official ADL CP schema and SCORM fourth-edition CAM sharedDataGlobalToSystem / RTE adl.data. See ADR-089 for schema/API/encoding profiles. This implementation does not remove asset/duration/selection/objective or full conformance/reference/platform/production requirements.

Validation: cross-package/enrollment sharing for one learner; learner and unofficial separation; readonly/unmapped denial; concurrent explicit writers with CMI-only and old-receipt counterexamples; immutable keys/foreign-key integrity; store-count and tenant-capacity rollback; real DB/server reopen; populated schema-48 local-state migration without projection; security revocation and diagnostic redaction; coherent whole-DB backup/offline restore. Authored built browser covers system stores through save/resume/lost ACK/next-SCO/proof and asserts only two explicit writes.
