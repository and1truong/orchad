# ADR-092 — trusted selection and randomization

Status: implemented tested profile; full reference/conformance/platform/production gates remain open.

Translate original IMS randomizationControls for 2004 editions 2–4: selectionTiming/randomizationTiming never, once or onEachNewAttempt; selectCount XML nonnegative integer 0–2048 (the package activity/resource bound); reorderChildren boolean. Defaults are never/no reordering/no count. Replace the whole XML group on collection override, independently from other control groups. Malformed recognized definitions, including unselected organizations, fail import. Controls affect cluster children; this does not invent leaf selection or allow a client-chosen subset. Each-attempt timing is an explicit tested pinned-engine behavior; do not infer every commercial/edition conformance profile mandates identical behavior.

Pinned engine reuse exposed selection defects. pear-selection-v2 is a checksum-locked MIT ESM adaptation that retains the existing three direct-log removals and corrects: zero count rejected by the setter; subsequent each-attempt selection starting from an already excluded pool; selection/randomization occurring in delivery after a candidate had already been chosen; and a duplicate decision at delivery after traversal prepared the exact parent attempt. The traversal prepares a fresh non-suspended attempt, and delivery uses that pool/order once. Private pending metadata is synchronous engine bookkeeping, not a client API or a new authority source. Engine selection algorithms/rule/rollup processing are reused. Original version is still 3.4.5; behavior marker is explicit in snapshots/proofs/support diagnostics.

Exact adapted ESM SHA-256: 206daee49525dbf352bf9d6920f6d1ccc03ad9e8834db57a8d7d5ee2efb93cc0. The installation script accepts only the exact pristine source, known logging-only predecessor, or exact adapted bytes. Check replacement cardinality and final checksum, preserve copyright/MIT notices, and fail unreviewed bytes. Pristine install, logging-only upgrade and repeated adapted execution are verified. Unknown snapshot adaptation markers fail identity checks; known legacy 3.4.5 snapshots without the new marker remain readable. This is no longer described as logging-only adaptation.

Read-only context eligibility does not spend a first random subset; before an attempt exists, evaluate static delivery/rules without selection. Launch makes the real decision within the existing registration/launch transaction. Persist engine selectedChildIds, childOrder, selection/reorder flags and tracking in the existing trusted snapshot. Context, resume, stale/duplicate receipt and DB/server reopen retain that decision. An unselected activity cannot be delivered by explicit launch or content navigation. Zero selected children is a valid nondeliverable plan: fail delivery without a registration/proof, rather than silently selecting everything.

Proof requires every selected original SCO's accepted completion/pass/score policy AND trusted root rollup. Only an original count-limited selection cluster with a trusted completed selection decision can exclude its unselected subtree; hidden presentation, zero weight, preconditions or a count at/above pool size do not erase required evidence. Include cluster selected children/order in immutable proof. If no SCO remains selected, no empty proof is issued. Domain enrollment/retake/quiz/award policy stays independent.

Validation includes each edition selected-only proof, static context without registration writes, unselected launch denial, save/resume/receipt retry, once vs renewed root retryAll (previously excluded child may become selected), shuffle before candidate delivery exactly once, zero selection, never/count-at-or-above-pool behavior, hidden required SCOs, nested folder exclusion, group override/malformed definitions, legacy/unknown engine identity, real DB/server reopen and authored built browser lost-ACK selected proof/time/idempotency. All previous SCORM/learning/authorization/operations lanes must remain green because this changes pinned behavior.

References: [ADL fourth-edition Testing Requirements](https://adlnet.gov/assets/uploads/SCORM_2004_4ED_v1_1_TR_20090814.pdf), randomizationControls XML binding; [Rustici official sequencing model explanation](https://scorm.com/scorm-explained/technical-scorm/sequencing/sequencing-definition-model/); scorm-again 3.4.5 MIT ESM SelectionRandomization/traversal/delivery source and public persistence APIs. Rustici differential/account and actual authoring exports remain external gates, not claimed results.
