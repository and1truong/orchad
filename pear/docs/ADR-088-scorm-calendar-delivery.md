# ADR-088 — trusted calendar delivery windows

Status: implemented successor to ADR-087; epic #133 remains open.

Accept imsss:limitConditions beginTimeLimit/endTimeLimit on organizations and activities. Parse before engine construction; validate unused collections and unselected organizations too. Whole-group inline replacement clears collected window values just as it clears attempt limits. Preserve normalized instants in the trusted manifest/tree; reconstruct static configuration from the immutable original package, never client tracking data.

The admitted xs:dateTime profile requires positive four-digit Gregorian years, explicit Z or an offset up to ±14:00, and zero to three fractional digits. Validate leap years/month lengths before JavaScript can normalize invalid dates. Accept 24:00:00 only with a zero fraction and normalize to the next day; normalize offsets to UTC. Reject reversed windows. Zone-less/expanded-year/higher-precision values remain explicitly unsupported; no silently assumed local timezone or precision loss. This is a bounded profile, not exhaustive XML Schema conformance.

Use the pinned engine's begin/end checks and existing trusted host navigation transaction. Endpoints are inclusive. IMS SS UP.1 exempts untracked activities: omit their calendar windows from the executable tree while retaining the original manifest, because the pinned upstream calendar checker does not honor tracked itself. These are delivery limits, not a timer that kills active content. A client-valid request can expire before reaching the host; rejection rolls back CMI/time/navigation/proof, leaving the accepted sequence and revision unchanged. A request accepted within the window retains its normal replay/idempotency semantics. Client Date manipulation is not authority. No content-supplied host clock, new capability, schema migration or engine byte adaptation is introduced.

Absolute/experienced duration limits remain an open implementation requirement. Read-only inspection of pinned scorm-again 3.4.5 found absolute-duration getters alias configured limits, attempt startup resets that alias, and another limit checker compares experienced time for absolute limits. Accepting duration attributes directly would misexecute content. A later slice must correct those paths with version/provenance evidence and prove trusted clocks, suspended/resumed attempts and durable elapsed state. Optional-feature status in upstream standards does not remove the user's epic scope.

References: [official ADL/IMS limit schema](https://github.com/adlnet/SCORM-2004-4ed-SampleRTE/blob/master/xml/xsd/imsss_v1p0limit.xsd), [IMS SS UP.1](https://www.imsglobal.org/simplesequencing/ssv1p0/imsss_infov1p0.html), [XML Schema 1.0 dateTime](https://www.w3.org/TR/xmlschema-2/#dateTime), [pinned engine](https://github.com/jcputney/scorm-again/tree/v3.4.5). No external engine upload or licensed source reuse.

Validation: all three editions exercise before/start/end/after boundary, trusted reconstruction, live server expiry rollback and official required-SCO completion. Invalid dates, leap centuries, offsets, zone-less values, reversed intervals, unselected definitions and collected whole-group overrides are counterexamples. Built authored calendar-window fixtures exercise save/resume/lost ACK/next SCO/proof through the isolated shell.
