# ADR 026: Reviewed inline SCORM package profile
Status: accepted for synthetic development/identity fixtures; production runtime blocked.
Epic: #49, G05/G18. Stack: after #84.

## Decision
Freeze `pear-scorm12-inline/1`: a self-authored ZIP containing exactly a UTF-8 `imsmanifest.xml` and a single inline `index.html` SCO. Accept stored/deflated entries with CRC and matched contiguous local/central headers; reject paths, symlinks, encryption, descriptors, ZIP64, extra files, external resources, entities and unsupported XML. Bound raw upload at 8 MiB, manifest at 16 KiB, HTML at 1 MiB and expansion ratio at 100. This is a restricted profile, not full SCORM 1.2/2004 conformance or third-party interoperability.

Import stores immutable original bytes/hash and HTML in quarantine. Only an active content administrator can publish after explicit rights/code/hash review; review/import/retire use live roles, CAS, audit and atomic idempotency. Export returns exact original bytes only to content administrators. Shared media/package quotas are 128 MiB and 512 objects per tenant. Production import, review, export and execution remain closed until scanning, storage and runtime adapters are configured; no environment flag opens this adapter.

Human tracking consent creates a session-bound launch lease and short-lived ticket. The SCO runs in an opaque iframe with only scripts, CSP blocking fetch/subresources/forms/frames, and no parent cookies, DOM or Bridge access. Runtime messages require the current frame source, opaque origin, lease, nonce, record ID, bounded state and CAS. The parent uses human session/CSRF/epoch authorization; no import, launch or commit exists in agent tools. Only package metadata and own minimal reported results are semantic reads; suspend/location/runtime code/secrets are withheld.

The supported eight CMI state strings are status, location, suspend data, score raw/min/max, exit and session time. Supported read-only fields are opaque student ID, empty student name, mode, entry and accumulated reported time. The API exposes the eight SCORM 1.2 function names with explicit unsupported-element errors. `LMSCommit("")[=true]` means accepted into the parent queue, **not durable server success**. The human UI distinguishes pending, acknowledged and reconciliation-needed states. `LMSFinish` succeeds only after acknowledgment. This asynchronous transport differs from general SCORM runtime expectations and must not be advertised as conformant.

Reported cumulative session time adds only a monotonic delta per lease; duplicate commits and retransmission do not double-count. New launches rotate old leases, reset session time and restore private state. Retired packages deny new learners while retaining existing learners' immutable history/resume. Revoked sessions/accounts cannot replay prior commits. Runtime state, key, personal revision and audit commit atomically. Reported completion/score/time never enroll, submit official answers, grant certificates or alter observed study timers/award credit.

## Evidence and limits
Source tests cover original stored/deflated archives and CRC golden vector, malformed/hostile ZIP/XML, authority/CAS/audit rollback, exact retry, private state, lease/ticket rotation, restart/resume, retirement and zero official effects. The browser journey imports/reviews/byte-exports an original package, runs the actual iframe/API, awaits server persistence and resumes state after reload. CI results must be recorded against the exact published head; source existence alone is not a PASS.

Primary mapping reference: ADL xAPI-SCORM Profile, https://github.com/adlnet/xAPI-SCORM-Profile/blob/master/xapi-scorm-profile.md . The full SCORM 1.2 RTE specification was unavailable in this session; no full-spec compliance claim follows from that mapping.

Open: arbitrary multi-file packages/assets, sequencing/navigation/interactions/objectives, complete CMI/error semantics, synchronous general-runtime expectations, SCORM 2004/cmi5, third-party conformance, licensed package rights, hardened production scanning/storage/runtime, retention/compaction and real deployment.

Current delivery review: opaque sandbox and CSP isolate Pear authority and block the listed resource mechanisms, but do not guarantee zero network egress for arbitrary inline JavaScript. In particular, child self-navigation can issue an external request. Production-grade executable media/package egress isolation is a remaining CODE gap (DELIVERY-STATUS M1/M4/M7); existing fixture fetch-denial evidence is not a conformance or all-egress PASS. The restricted SCO profile rejects declared external assets/navigation before quarantine; dynamic script egress still requires an isolated runtime/network policy.
