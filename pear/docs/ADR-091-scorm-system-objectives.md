# ADR-091 — persistent learner-scoped system objectives

Status: implemented successor; full conformance/reference/production gates stay open.

Admit objectivesGlobalToSystem=true and its default for SCORM 2004 editions 2–4. Schema 50 stores mapped tracking values by tenant, learner and original targetObjectiveID, with revision, source registration and timestamp. Composite foreign keys and immutable key identity constrain storage. Store status/measure and fourth-edition ADL score/progress/completion fields, never manifest read/write flags. Local false retains registration scope. Preview and unbound practice remain private registration state by explicit Pear authority policy.

Load only targets declared in the selected original package, after live tenant/learner/package/binding/capability authorization. Restore through the pinned engine's public global-objective API; original mapInfo remains authoritative. Context availability must also load current authorized values, so UI availability and server delivery agree. An inherited objective can open a prerequisite in another package/enrollment but does not replace that enrollment's required durable per-SCO evidence, trusted rollup and proof policy.

Capture trusted engine tracking before and after checkpoint validation. Persist only materially changed field/known pairs whose original selected tree declares write permission, never an incoming client objective map or whole client snapshot. The engine processes local objective writes and rollup; Commit keeps the current activity active and does not end it. Ordered server transactions merge field deltas with current stored values; readonly/CMI-only activity, unchanged fields and exact receipt replay do not clobber later writes. This is a material-change concurrency policy, not a generic global-bucket CAS or an explicit content write-delta API.

System objective writes join CMI/time/sequencing/workspace/proof/receipt in one transaction. Failed persistence, learner count (4096), objective bytes (16 KiB) or tenant runtime capacity (64 MiB) rolls everything back. UTF-8 objective state/target bytes and bounded metadata are counted. Diagnostics remain aggregate-only. No agent runtime-data mutation tool is introduced.

Bootstrap masks global objective fields by current activity read maps, including global map/list, sequencing map, suspension backing map and inherited objective tracking copies. Read-permitted local objectives are initialized normally; unreadable raw score copies must be absent from the entire bootstrap JSON. Host sequencing retains complete trusted state and does not accept client snapshots as authority.

Populated schema-49 migration preserves local tracking/history without creating global state or official proof. Real DB/server reopen and whole-DB backup/offline restore retain coherent values; restore revokes sessions/capabilities. Package security revocation retains accepted tracking but blocks even that package's old receipt replay. Production archival/retention/encryption/deployment decisions remain separate and unimplemented gates.

References: official ADL SCORM 2004 CAM objectivesGlobalToSystem, IMS SS objective mapping/read/write and ADL fourth-edition objective extension; pinned scorm-again 3.4.5 public restore/serialize/Terminate APIs. No engine behavior bytes are changed. This tested profile does not establish standard certification or remove asset, duration, selection, reference, platform or production requirements.

Validation: each 2004 edition cross-package/enrollment prerequisite denial before accepted termination and admission afterward; independent proof requirements; readonly/forged objective and snapshot counterexamples; unofficial/learner separation; concurrent registrations, receipt retry, persistence/capacity/count rollback; fourth-edition raw/min/max field persistence and unreadable bootstrap-copy redaction; populated migration, actual reopen/revocation, coherent backup/offline restore; built browser save/resume/lost ACK/next-SCO/proof with exactly one material system-objective revision.
