# ADR-010: human submissions and instructor-led sessions

Internal synthetic scope, 2026-10-06. Stack parent: media PR #68. No storage/video/calendar provider or live instructor/account integration has been configured.

A course lesson may require a PDF submission or instructor-led attendance. Backend derives the mixed `human_attestation_review_and_quiz` policy; human acknowledgement cannot replace either review. All lessons still must complete before the pinned quiz can start. Upload, booking, a script result or a model assertion never creates a certificate. Official completion still requires the authoritative passing assessment.

Submission policy pins rubric, 1–10 attempts and pass threshold into the immutable course version. Learners upload an owned immutable PDF bound to their own active unlocked enrollment/lesson, then explicitly confirm submission. Pending work blocks resubmission; a human failed review permits another attempt up to the pin. Submitted artifacts, review score/reason/assessor/time and failed history survive restart. Admin or an active course-delegated Assessor can read files and grade. Content Admin may delegate assessors but cannot inspect or grade learner files. Private evidence cannot become publishable course assets. Source file bytes, rubrics and review reasons are human-only. Operational audit records IDs rather than private review text.

Session IDs are globally unique and pinned to tenant/course/lesson. First publication creates the shared session record atomically. Republishing identical definitions preserves capacity across course versions; changing start/end/cutoff/location/capacity under an existing ID fails. Rescheduling requires a new session ID and explicit revised course version; existing enrollment history retains its original session. Up to eight slots per lesson and forty booking history entries bound results. Starts/ends/cutoff accept explicit ISO offsets or UTC, with valid calendar dates and IANA display timezone. Ambiguous offset-free local time fails. Start < end and cutoff <= start. DST fallback fixtures distinguish the two 01:30 instants in America/New_York.

Bookings are atomic inside the same immediate transaction/CAS/idempotency/audit controller as other writes. Only the current learner's active unlocked lesson is bookable before cutoff. Capacity counts booked/present seats; duplicate active learner/session and enrollment/lesson slots fail. Cancellation releases an unassessed upcoming seat and retains history. Dynamic withdrawal, assignment cancellation and account deactivation release unassessed bookings; returning membership does not silently rebook. Course-delegated humans record present/absent with a reason only after the pinned session has started. Present completes that lesson; absent does not. Final review/attendance is immutable. Current role/delegation is rechecked before valid retry returns its original result. No attendance or grading tools exist in agent catalogs.

The operations assistant group exposes bounded own status, booking/cancellation and delegated queue metadata. It shares canonical personal/library CAS and preserves the host binding/approval rules. Human UI supports authoring policies/slots, submission/review, timezone/availability, booking/cancel and attendance. No agent runtime is embedded in Pear.

An authenticated learner can download an ICS for their own active booking. UTC DTSTART/DTEND avoids ambiguous local-time export; display timezone is disclosed. CRLF content lines, required UID/DTSTAMP, escaping and UTF-8-safe 75-octet folding follow [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545.html). This is a private calendar file, not a live Google/Outlook calendar integration. HTTPS meeting URLs are ordinary human links; no meeting is provisioned or attendance inferred from provider telemetry.

Production upload scanner/quarantine/storage remains the inherited closed gate. Provider calendar/video connectors, exact reference reschedule/notification policies and any migration-specific assessment behavior remain open. Internal tests and fixtures do not establish connector or full Go1 parity.

Supporting synthetic-auth correction: successful shared-IP logins do not consume or reset the failed-guess budget (30/minute). A separate total request cap (120/minute) bounds password work; Retry-After describes temporary denial. Production password login remains disabled. Domain/HTTP tests cover both cumulative failures and valid multi-user use.
