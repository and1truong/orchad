# ADR-089 — fourth-edition registration-local shared data

Status: implemented local-scope successor to ADR-088. System-global shared data remains required work; epic #133 remains open.

Parse fourth-edition adlcp:data/map on SCO activities, targetID and readSharedData/writeSharedData defaults (true/false). Validate namespace, placement, cardinality, duplicates, bounded nonempty URI identifiers, boolean vocabulary, edition and every organization's definitions. Parse the organization sharedDataGlobalToSystem boolean; its default true remains explicitly refused at playback until a durable system-scope store is implemented. Local admission requires explicit false. Never silently turn a global store into a local store.

Use the pinned engine's current-activity mappings and shared backing snapshot. Runtime exposes the fourth-edition adl.data count/children/id/store model; previous editions reject it. IDs are LMS-owned; unknown indices cannot create stores. Content writes enter a separate bounded delta, never the CMI object. Commit and Terminate queue the exact delta with CMI/navigation/sequence; queue rejection retains it, successful queue acceptance clears it, and lost ACK retries the same frozen payload. Aggregate fourth-edition state/data queue size remains 512 KiB. Store values have a bounded 64000 UTF-16-code-unit profile; supplementary-Unicode SPM conformance remains open. No durable success is reported until server ACK.

The trusted host replays only writes permitted by the current activity's immutable map, after Initialize but before navigation. Read-only/unmapped/non-string/oversized values fail and roll back. CMI/time/shared backing state/navigation/proof/receipt share the existing transaction and storage quota. Shared values are content-reported working data, not official learning proof. Each technical retake within a registration preserves shared stores while clearing its new CMI/sequencing attempts. New registration/enrollment/learner and preview/practice registrations remain separate. No mutable old attempt history, schema migration, engine byte adaptation or authority expansion.

Bootstrap snapshots disclose only stores the current activity can read. Other backing stores and write-only previous values are removed from client JSON, rather than relying on API access errors to hide payloads. Host snapshots retain them durably. Metadata/agent diagnostics remain redacted; human support/whole-DB backup follow existing authorization/privacy restrictions.

References: [official ADL CP schema](https://github.com/adlnet/SCORM-2004-4ed-SampleRTE/blob/master/xml/xsd/adlcp_v1p3.xsd), SCORM 2004 fourth-edition CAM data/sharedDataGlobalToSystem and RTE adl.data. This is a local-scope implementation slice, not an owner-approved exclusion of system-global semantics.

Validation covers cross-SCO write/read, write-only/read-only/immutable IDs, hidden backing values, technical retake without history mutation, learner/preview separation, exact lost-ACK receipt replay, real DB/server reopen, queue rejection/delta reset, malformed/oversized/unauthorized writes and schema/edition/global-scope negatives. Authored built-browser content uses shared notes through save/resume/lost ACK/next-SCO/proof.
