# ADR-051: Human question checks and objective progression
Epic #49 G06/G12/G16. Base: PR #109.

Authors may require objective responses to be checked correct before advancing in the stored per-attempt question order, with optional after-question answer release. Original declared settings remain off by default. Long answers may coexist with after-question release without a progression gate, and still require final authorized assessment. Correct-before-continuing plus long answer is rejected explicitly: the reference composition needs a verified fixture.

The human-only check write accepts a saved response fingerprint and runs through live owner, tenant, current pinned content/group rights and active assignment checks before receipt lookup and inside the same IMMEDIATE transaction. SHA256 of canonical response plus monotonically increasing answer version prevents old successful check replay after a response changes and is restored. Identical saved responses retain checks; changed earlier responses invalidate their check and later checks while retaining hidden later drafts. Invalidated later states also advance their context version, so their old check receipts cannot be reused when earlier questions reopen them. Submit independently requires all current checks correct; bypassing the UI cannot complete learning.

Migration 033 persists answer/check versions per attempt/question. Checks update neither submitted state, score, certificate, award progress nor completion notifications. A human can see configured correct/try-again state and, under after-question release, objective keys for checked current responses. Never-release keeps keys hidden. Final graded release and pending manual privacy retain prior rules. The learner bridge sees eligible prompts only, no saved responses, fingerprints, check states, correctness results or keys. Operational audit excludes fingerprints/responses; ordinary human-only receipts follow existing retention rules.

Five domain/randomized-order/HTTP/replay/audit/SQLite reopen regressions and one author/learner EN/VI mobile browser scenario are authored. Exact-head CI pending. The canonical Bridge contract and all byte/schema limits remain unchanged. Incorrect-only retries, previous response preferences, author preview, latest-quiz migration and rich author formatting are still OPEN; no full reference equivalence, production deployment or accessibility certification claim.
