# Threat model

Trusted: bundled host UI, Rust native code, owned sidecar, OS user. Untrusted: guest app, tools/descriptions/context/results, model output, HTTP clients. A compromised same-user OS process or compromised host bundle is outside this POC's protection.

Guest has no privileged host/window/process/filesystem permission. Custom commands are enrolled explicitly with AppManifest::commands; only host label receives open_guest and host_request. guest receives only guest_reply for one allowlisted remote origin. It cannot grant itself approval: native verifies guest label/runtime URL, outstanding correlation, current binding, and per-document nonce. Reply data is size limited and contract validated. Tool effects never grant automatic domain invocation privileges. Serialize request JSON rather than interpolate arguments.

Navigation immediately revokes targets and approvals; fragment-only changes keep the binding. Document nonce checks prevent queued old dispatch code from running on a reloaded page. Context document mismatch either rebinds (same app/page instance reporting a new documentId: native installs the new document before forwarding the reply, revoking old-document approvals and cached tools; calls pinned to the old documentId fail) or, when the app/page changed, revokes the policy target. Backend UNAUTHORIZED/FORBIDDEN revokes policy target. Cancellation and timeouts never replay mutations; timed-out or cancelled dispatches notify native (dispatch-timeout) so stale reply state is dropped. Page-declared inputSchemas pass a host-safe keyword/depth/size check before Ajv compiles them — schema-registry keywords ($id/$schema) and quadratic-cost uniqueItems are also excluded, so a hostile schema can neither poison the shared Ajv instance nor stall or crash the single-threaded sidecar. Sidebar requests cannot inject native event envelopes ('kind' is stripped at the command boundary). App backend still must atomically authorize/validate/revise/deduplicate: fixture is only a test double.

MCP binds IPv4 loopback. Exact Host and bearer auth required; every browser Origin is rejected. Client sessions are pinned to credential identity and capped at 256 (oldest evicted), bounding sidecar memory under session churn. Scope/target/expiry/revoke intersect with approval policy. Pending approvals expire, are capped at 64, and a visible trusted UI heartbeat is required. Pairing secrets are ephemeral, hashed in memory, never sent to guest or included in audit. Gateway secrets stay in trusted React memory.

Residual gaps: no native runtime security verification, no guest renderer crash event handling, fixed allowlist, same-WebView SSO redirects only and untested, no secure durable pairing store, no packaged Node runtime, and only one fixed-layout guest. No signed/notarized release. Desktop deployment requires enterprise approval and endpoint policies.
